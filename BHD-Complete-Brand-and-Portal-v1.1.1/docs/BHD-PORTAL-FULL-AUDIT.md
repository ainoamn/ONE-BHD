# تقرير شامل لبوابة BHD

> **الموقع:** https://one-bhd.vercel.app  
> **المستودع:** https://github.com/ainoamn/ONE-BHD  
> **تاريخ المراجعة:** 16 أغسطس 2026  
> **نسخة النشر:** `BHD-Complete-Brand-and-Portal-v1.1.0` على Next.js 16  
> **طبيعة النظام:** بوابة تعريفية عامة — ليست تطبيقاً مالياً ولا قاعدة بيانات مركزية

هذا التقرير يصف ما يعمل فعلياً في الكود المنشور، لا ما هو مرسوم للمستقبل فقط.

---

## 1. الخلاصة التنفيذية

بوابة BHD هي الواجهة الأم لشركة **بن حمود للتطوير**. تعرض الشركة ووعدها **ابنِ أحلامًا أكبر**، وتوجّه الزائر إلى منتجات مستقلة (وازن، حسابي، عين عُمان، نَسَب، متجر BHD، مكتب BHD).

**ما هي:** موقع تسويقي وهويّة ومشغّل روابط.  
**ما ليست:** حسابات مستخدمين، مدفوعات، تخزين بيانات تشغيلية، أو دخول موحّد منفّذ.

هذا التصميم مقصود: فصل المنتجات يقلل أن يؤدي عطل أو اختراق في تطبيق واحد إلى سقوط المنظومة كلها. الثمن هو أن «حساب BHD» و«هوية BHD» ما زالا رؤية، لا خدمة حيّة.

## 4. طريقة البناء

```
الزائر → HTTPS (Vercel) → Next.js 16 (App Router) → صفحات React
                                              ↓
                                    ملفات ثابتة في public/
                                    بيانات المنتجات في app/lib/products.ts
```

| الطبقة | التقنية |
|---|---|
| الإطار | Next.js 16.2.6 + React 19 |
| الاستضافة | Vercel — مشروع `one-bhd` |
| مجلد البناء | `BHD-Complete-Brand-and-Portal-v1.1.0` |
| Node | 22+ |
| الأنماط | CSS عالمي + Tailwind 4 |
| الخط | `next/font` — IBM Plex Sans Arabic وInter |
| الاختبار | `npm test` يبني ثم يفحص ملفات الحماية والهوية |
| المصدر الأصلي | قوالب vinext/Cloudflare؛ الإنتاج حُوّل إلى Next.js |

**لا توجد قاعدة بيانات تشغيلية.** `getDb()` يرمي خطأ عمداً. Drizzle وvinext وWrangler بقيت في الحزمة من القالب ولم تُستخدم في الإنتاج.

## 5. الإيجابيات

1. نطاق أمني ضيق: لا كلمات مرور ولا بطاقات ولا ملفات مستخدمين في البوابة.
2. رؤوس حماية متصفح واضحة ومفعّلة على كل المسارات.
3. `X-Powered-By` معطّل.
4. صفحة الدخول غير قابلة للفهرسة ولا تُخزَّن.
5. CSP تمنع التضمين في إطارات خارجية (`frame-ancestors 'none'`).
6. صلاحيات المتصفح الحساسة معطّلة (كاميرا، ميكروفون، موقع، دفع).
7. HSTS لسنة كاملة مع `includeSubDomains`.
8. سياسة خصوصية صادقة: لا تدّعي تشفير بيانات غير موجودة.
9. فصل المنتجات معماري صحيح للتوسع.
10. أصول العلامة عالية الدقة وقابلة للتنزيل.

---

## 6. السلبيات والحدود

1. البوابة لا «تربط» المنتجات تقنياً بعد؛ الربط حالياً روابط خارجية.
2. نطاق الإنتاج `one-bhd.vercel.app` بينما `robots.txt` و`security.txt` ما زالا يشيران إلى `bhd-om.com`.
3. CSP فيها `'unsafe-inline'` للسكربت والأنماط — تضعف الحماية من XSS مقارنة بـ nonce صارم.
4. بقايا القالب: vinext، Cloudflare plugin، chatgpt-auth غير مستخدم.
5. اختبارات الإنتاج تفحص الملفات لا سلوك المتصفح الحقيقي (E2E).
6. لا مراقبة أخطاء تطبيقية موثّقة في المشروع.
7. لا نطاق مخصص ولا بريد أمني في `security.txt` (جهة الاتصال GitHub فقط).
8. بعض المنتجات تفتح مستودع GitHub بدل تطبيق حي.
9. الاسم في `package.json` ما زال `site-creator-vinext-starter`.

## 7. الأمان والحماية والتشفير — ما هو موجود فعلاً

### 7.1 أثناء النقل

- **HTTPS/TLS** توفره Vercel لكل الزيارات على النطاق الحي.
- **HSTS** يفرض HTTPS لمدة 31536000 ثانية.
- **upgrade-insecure-requests** في CSP.

هذا تشفير **أثناء النقل**. لا يوجد تشفير **عند التخزين** في البوابة لأنه لا تُخزَّن بيانات مستخدم.

### 7.2 رؤوس المتصفح (من `next.config.ts`)

| الرأس | القيمة العملية |
|---|---|
| Content-Security-Policy | مصادر من نفس الأصل؛ لا إطارات؛ لا كائنات |
| X-Frame-Options | DENY |
| X-Content-Type-Options | nosniff |
| Referrer-Policy | strict-origin-when-cross-origin |
| Permissions-Policy | تعطيل كاميرا/ميكروفون/موقع/دفع/USB |
| Cross-Origin-Opener-Policy | same-origin |
| Cross-Origin-Resource-Policy | same-origin |
| Strict-Transport-Security | max-age=31536000; includeSubDomains |

### 7.3 ما ليس موجوداً

- لا كلمات مرور تُشفَّر (لا حسابات).
- لا مفاتيح تشفير في الخادم للتطبيق.
- لا MFA / مفاتيح مرور / جلسات.
- لا جدار تطبيق مخصّص فوق ما تقدمه Vercel افتراضياً.
- لا تقييد معدل على `/healthz` أو الصفحات.
- لا سجل تدقيق لعمليات مستخدم.

### 7.4 الإفصاح الأمني

`public/.well-known/security.txt` يحدد التواصل عبر GitHub وينتهي في 16 أغسطس 2027. المسار القانوني فيه `bhd-om.com` وليس النطاق الحي الحالي.

## 9. الثغرات والمخاطر (تقييم واقعي)

لا يُقدَّم هنا استغلال. التقييم للدفاع والتطوير.

| الخطر | الشدة الحالية | لماذا |
|---|---|---|
| XSS عبر سكربت مضمّن | منخفضة–متوسطة | CSP تسمح `unsafe-inline`؛ لا يوجد إدخال مستخدم مخزَّن |
| Clickjacking | منخفضة | ممنوعة بالرؤوس |
| تسريب بيانات شخصية من البوابة | منخفضة جداً | لا تُجمع |
| التصيّد عبر نطاق vercel.app | متوسطة للمستقبل | نطاق فرعي عام أسهل للخلط من نطاق الشركة |
| روابط خارجية إن تغيّر مستودع | منخفضة | الروابط ثابتة في الكود وتُراجع مع Git |
| معلومات من `/healthz` | منخفضة | لا تكشف أسراراً |
| اعتماديات npm غير مستخدمة | منخفضة | تزيد سطح التوريد دون فائدة إنتاج |
| عدم تطابق النطاق في robots/security.txt | منخفضة | يربك الإفصاح والأرشفة |

**خلاصة أمنية:** البوابة في وضعها الحالي منخفضة الخطورة لأنها بلا بيانات حساسة. الخطر يرتفع فور إضافة حسابات أو نماذج أو ذكاء اصطناعي خادم دون هوية وتشفير وتدقيق.

## 10. طريقة العمل على المشروع

```bash
git clone https://github.com/ainoamn/ONE-BHD.git
cd ONE-BHD/BHD-Complete-Brand-and-Portal-v1.1.0
npm install
npm run dev          # http://localhost:3000
npm run build
npm test
```

- عدّل الصفحات تحت `app/`.
- عدّل قائمة المنتجات في `app/lib/products.ts`.
- عدّل الحماية في `next.config.ts`.
- ادفع إلى `main` ثم انشر من جذر المستودع: `npx vercel --prod --yes` مع Root Directory = المجلد أعلاه.
- سياسة الإصدارات: ادمج أحدث مجلد تسليم في `v1.1.0` ثم في `v1.0.0`.

## 11. الربط مع بقية المنظومة

**اليوم**

- الربط = روابط HTTPS إلى تطبيقات Vercel أو GitHub.
- لا مشاركة كوكيز ولا JWT ولا قاعدة مشتركة.

**المسار الصحيح للترقية (لا تخلط قواعد البيانات)**

1. بناء **خدمة هوية مستقلة** (BHD Identity) بمعيار OpenID Connect وتفويض التطبيقات.
2. كل منتج يبقى عميلاً به `client_id` ومفاتيحه وجلسته المحلية.
3. البوابة تصبح نقطة دخول و«مشغّل» بعد تسجيل الدخول، لا مخزناً لبيانات وازن أو حسابي.
4. لا تُقرأ قواعد بيانات المنتجات من البوابة.
5. عند الحاجة لذكاء اصطناعي: بوابة خادمة خاصة، لا مفاتيح في المتصفح، وتقليل البيانات.

## 12. خطة الترقية المقترحة

### المرحلة أ — ضبط الإنتاج الحالي (أيام)

- توحيد `robots.ts` و`security.txt` على `https://one-bhd.vercel.app` أو ربط النطاق الرسمي.
- CSP بـ nonce بدل `unsafe-inline` قدر الإمكان.
- حذف أو عزل vinext وchatgpt-auth من مسار الإنتاج.
- `npm audit` دون كسر البناء.
- بريد إفصاح أمني.

### المرحلة ب — النطاق والثقة (أسابيع)

- نطاق الشركة + شهادة TLS عبر Vercel.
- سياسة خصوصية محدَّثة قبل أي نموذج.
- صفحة حالة المنتجات مربوطة بمصدر حقيقة واحد.

### المرحلة ج — الهوية (أشهر)

- BHD Identity + MFA/مفاتيح مرور.
- ربط وازن وحسابي ونَسَب كعملاء OIDC.
- سجلات تدقيق وتحديد معدل ومحاولة دخول.

لا تُنفَّذ المرحلة ج داخل مجلد البوابة كـ «نموذج تسجيل» شكلي.

## 13. الحكم النهائي

البوابة **صالحة كواجهة علامة ودليل منتجات**، ومحمية بما يناسب موقعًا بلا حسابات: نقل مشفّر، رؤوس متصفح صارمة نسبياً، وعدم جمع بيانات.

هي **غير جاهزة** كمنصة هوية أو تشغيل مركزي. الإيجابية الكبرى هي الصدق المعماري: المنتجات مستقلة. السلبية الكبرى هي أن تجربة «منظومة واحدة» ما زالت تسويقية حتى تُبنَى الهوية بشكل صحيح.
